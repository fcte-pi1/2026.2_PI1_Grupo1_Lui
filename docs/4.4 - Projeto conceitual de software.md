# Especificação de Protocolo e API de Telemetria (1 Hz) - Micromouse (ESP-NOW + Gateway Serial)

## 1. Visão Geral da Arquitetura

O sistema de telemetria opera via protocolo de rádio sem fio **ESP-NOW** (protocolo de camada de enlace em 2.4 GHz proprietário da Espressif, operando sem a necessidade de roteador Wi-Fi). A transmissão ocorre em uma frequência nominal de **1 Hz** (um envio a cada 1000 ms).

Para integrar a telemetria do robô ao computador de monitoramento, utiliza-se uma arquitetura baseada em **Gateway Receptor Dedicado**:

```text
+--------------------------+                      +--------------------------+
|   ESP32 Emissor (Robo)   |       ESP-NOW        | ESP32 Receptor (Bancada) |
|   - Amostragem a 1 Hz    | ===================> | - Gateway / Bridge       |
|   - Payload: Struct C    |   (Pacote Binario)   | - Valida e converte      |
+--------------------------+                      +--------------------------+
                                                               |
                                                               | Stream Serial / USB (JSON a 115200 bps)
                                                               v
+--------------------------+                      +--------------------------+
|      Dashboard Web       |      WebSocket       |     Servidor Backend     |
|  - Renderizacao da grade | <=================== | - Ingestao da porta COM  |
|  - Rastro e Metricas     |    ws://... (JSON)   | - Broadcast e Banco DB   |
+--------------------------+                      +--------------------------+
```

1. **ESP32 Emissor (Robô):** Coleta dados dos sensores, odometria, paredes e bateria; empacota em uma estrutura binária em C (`struct`) e transmite pelo ar via ESP-NOW para o endereço MAC do receptor a cada 1 segundo.
2. **ESP32 Receptor (Gateway USB):** Conectado à porta USB da estação base. Recebe a `struct` binária, converte para string JSON e envia pela interface Serial/UART (115200 bps).
3. **Servidor Backend:** Lê continuamente a porta serial USB (`/dev/ttyUSBx` ou `COMx`), valida o pacote e o redistribui via **WebSocket** para o front-end, persistindo também os dados no banco de dados para consultas históricas.
4. **Dashboard Web:** Interface gráfica que consome o WebSocket e atualiza o mapa (4x4, 8x4, 12x4) e indicadores em tempo real.

---

## 2. Camada de Rádio: Payload Binário ESP-NOW (`struct` em C)

No firmware do robô, a transmissão aérea utiliza uma estrutura compactada para garantir menor consumo de rádio, imunidade a ruídos e transmissão quase instantânea (< 5 ms):

```c
typedef struct __attribute__((packed)) {
    uint32_t timestamp_ms;     // Tempo decorrido de corrida (ms)
    uint8_t  labirinto_id;     // 1: 4x4, 2: 8x4, 3: 12x4
    uint8_t  status_id;        // 0: AGUARDANDO, 1: MAPEANDO, 2: SPEED_RUN, 3: COLISAO, 4: CONCLUIDO, 5: TIMEOUT
    uint8_t  desafio_cumprido; // 0: Nao, 1: Sim
    uint8_t  bateria_pct;      // 0 a 100 %
    uint16_t bateria_mv;       // Tensao em milivolts (ex: 7420 mV = 7.42 V)
    int16_t  velocidade_atual; // Velocidade instantanea em cm/s
    int16_t  velocidade_media; // Velocidade media acumulada em cm/s
    uint8_t  coluna;           // 0: 'A', 1: 'B', 2: 'C', 3: 'D'
    uint8_t  linha;            // 1 a 12
    uint8_t  paredes;          // Bitmask: bit0=N, bit1=S, bit2=L, bit3=O
} TelemetriaPacket;
```

## 3. Camada Serial (Gateway ESP32 -> Backend)

O ESP32 receptor converte os dados binários recebidos e emite pela porta USB uma linha de texto formatada em JSON a cada segundo:

* **Baud Rate:** `115200 bps`
* **Delimitador de Frame:** Quebra de linha (`\n`)

---

## 4. Camada de Aplicação: WebSocket API

### 4.1 Detalhes de Conexão

* **Protocolo:** WebSocket (RFC 6455)
* **Endpoint:** `ws://<host>:<porta>/ws/telemetria`
* **Frequência:** 1 Hz (1 mensagem por segundo)
* **Formato:** JSON em UTF-8

### 4.2 Payload JSON em Tempo Real

```json
{
  "timestamp_ms": 142000,
  "labirinto": "8x4",
  "status": "MAPEANDO",
  "desafio_cumprido": false,
  "bateria_pct": 78,
  "bateria_volts": 7.42,
  "velocidade_atual": 35.0,
  "velocidade_media": 28.5,
  "posicao": {
    "coluna": "B",
    "linha": 4
  },
  "paredes": {
    "norte": false,
    "sul": true,
    "leste": true,
    "oeste": false
  }
}
```

## 5. Dicionário de Dados

Todos os campos são estritamente **obrigatórios**:

| Campo | Tipo | Unidade | Descrição / Restrições |
| :--- | :--- | :--- | :--- |
| `timestamp_ms` | Inteiro | ms | Tempo decorrido de prova ($\ge 0$, limite de 10 min: 600.000 ms). |
| `labirinto` | String | - | Tipo de grade em execução: `"4x4"`, `"8x4"` ou `"12x4"`. |
| `status` | String | - | Estado FSM do robô: `"AGUARDANDO"`, `"MAPEANDO"`, `"SPEED_RUN"`, `"COLISAO"`, `"CONCLUIDO"`, `"TIMEOUT"`. |
| `desafio_cumprido` | Booleano | - | `true` se alcançou a célula objetivo com sucesso; `false` caso contrário. |
| `bateria_pct` | Inteiro | % | Carga restante estimada (0 a 100%). |
| `bateria_volts` | Float | V | Tensão da bateria medida via ADC (ex: 7.42 V). |
| `velocidade_atual` | Float | cm/s | Velocidade instantânea estimada pela odometria. |
| `velocidade_media` | Float | cm/s | Velocidade média acumulada na prova. |
| `posicao.coluna` | String | - | Coluna atual mapeada (`"A"`, `"B"`, `"C"` ou `"D"`). |
| `posicao.linha` | Inteiro | - | Linha atual mapeada (1 a 4, 1 a 8 ou 1 a 12). |
| `paredes.norte` | Booleano | - | Detecção de parede física ao Norte da célula atual. |
| `paredes.sul` | Booleano | - | Detecção de parede física ao Sul da célula atual. |
| `paredes.leste` | Booleano | - | Detecção de parede física ao Leste da célula atual. |
| `paredes.oeste` | Booleano | - | Detecção de parede física ao Oeste da célula atual. |

## 6. Tratamento de Confiabilidade e Watchdog

* **Watchdog de Enlace RF (3 segundos):** Por operar em cadência nominal de 1 Hz, caso o backend fique 3000 ms consecutivos sem ler um pacote válido da porta serial, o status na interface muda automaticamente para `CONEXAO RF PERDIDA`.
* **Descarte de Pacotes Corrompidos:** A biblioteca ESP-NOW possui verificação CRC de hardware embutida; pacotes com ruído de rádio são descartados automaticamente pelo ESP32 receptor antes do envio para a porta serial.
* **Persistência Pós-Desafio:** Ao término da prova (`status: "CONCLUIDO"` ou após colisão/timeout), o backend consolida a corrida no banco de dados para permitir a consulta posterior individual por labirinto ou geral.
